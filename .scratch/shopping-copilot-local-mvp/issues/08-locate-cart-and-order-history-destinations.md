# 08 — Locate cart and order-history destinations

**What to build:** Distinguish locating from activating while supporting cart, checkout, account, and newest-order guidance with safe authentication handoff.

**Blocked by:** 07E — Integrate real intent into Shopping Tasks.

**Status:** resolved for the Controlled Storefront local MVP (2026-09-24)

The subsequent v3 semantic repair no longer requires every real-model navigation request to match the legacy locate/open regex. Source-anchored intent may choose a canonical allowed destination; ambiguity, mixed authority, prompt override, and downstream browser safety remain checked. A single-use previous verified destination is available for natural followups across the four allowed destinations. This is not full conversation history, credential handling, or permission to execute a Mutation. The existing login-loop and Bridge sequence repairs remain required regressions. See the current evidence and remaining verification in `PROJECT_CHECKPOINT.md`.

- [x] “Where is” requests Spotlight the relevant element and stop without activating it.
- [x] Explicit “open” or navigation requests move to the requested destination.
- [x] The Shopper can reach fictional account order history and Spotlight the newest order.
- [x] A logged-out account route pauses and asks the Shopper to authenticate directly.
- [x] Credentials and one-time codes are never read or entered by the Copilot; direct Snapshot and Action regressions cover login identifiers and one-time codes.
- [x] Evaluation Cases distinguish locate, navigate, authenticated, and logged-out behaviour; all seven scripted browser cases pass.

The Intent Boundary and scripted planner share one vocabulary for the four supported destinations (cart, checkout, account, orders), checked against the Storefront Definition. Clear Shopper locate/open language and a single supported destination can repair a dropped model mode or target. Conflicting destinations or modes ask a trusted question without a browser Action; model-only navigation and product/navigation conflicts cannot silently authorize another Action. English, Arabic, and Franco-Arabic direct regressions cover these rules, prompt override, and clarification answers.
